# Запись на звонок

[![hexlet-check](https://github.com/burunin-aleksandr/ai-for-developers-project-386/actions/workflows/hexlet-check.yml/badge.svg)](https://github.com/burunin-aleksandr/ai-for-developers-project-386/actions)

Упрощённый сервис бронирования времени в духе Cal.com: админ управляет своими событиями, гость выбирает день в календаре месяца, свободный 30-минутный слот и записывается. Записи видны на публичной странице «Предстоящие события».

Демо-проект без авторизации, базы данных и деплоя — всё работает локально, состояние живёт в памяти сервера и сбрасывается при перезапуске.

Учебный проект Хекслета: https://ru.hexlet.io/programs/ai-for-developers
Как это должно работать: https://files.hexlet.app/a/2ipc5m

## Стек

| Слой | Технологии |
|---|---|
| Спецификация | TypeSpec → `spec/dist/openapi.yaml` → генерированный TypeScript-клиент |
| Сервер | Fastify + TypeScript, хранение в памяти |
| Клиент | React 19 + Vite + `openapi-fetch` |
| Тесты | Vitest: HTTP API через `app.inject`, страницы через React Testing Library |
| Монорепо | pnpm workspace (`spec/`, `server/`, `client/`) |

Часовые пояса: хранение в UTC, отображение в UTC+3 (захардкожено). Окно бронирования — 09:00–18:00 UTC+3, фиксированная сетка 30-минутных слотов (18 в день), слоты считаются на лету для просматриваемого месяца.

## Быстрый старт

Требования: Node 26 (см. `.nvmrc`), pnpm 12.

```bash
git clone https://github.com/burunin-aleksandr/ai-for-developers-project-386.git
cd ai-for-developers-project-386
nvm use                # Node 26
pnpm install
pnpm dev               # сервер на :3000, клиент на :5173 (Vite проксирует API)
```

Откройте http://localhost:5173.

Демо-данные (2 события админа + 2 записи гостей) загружаются **вручную**, при старте сервера — никогда:

```bash
pnpm fixtures           # пока сервер запущен; другой адрес — через BASE_URL
```

Чистый старт без фикстур показывает свободную сетку, а страница событий — «Пока нет событий».

## Как это работает

1. Лендинг «Calendar» → «Записаться →».
2. Экран записи: «Информация» | «Календарь» | «Статус слотов». День не выбирается автоматически — сначала «Выберите дату в календаре.».
3. Клик по дате → слоты диапазонами («09:00 - 09:30») со статусами; клик по свободному → «Продолжить».
4. Подтверждение: имя и email → «Подтвердить запись». «Изменить» возвращает к выбору слота.
5. Успех: «Бронь подтверждена. До встречи!» + «Забронировать еще».

Публичная страница «Предстоящие события» показывает будущие записи (имя, email, слот, момент создания).
Админка — только управление событиями админа — открывается по адресу `http://localhost:5173/#admin` и не ссылается из навигации.

## Команды

| Команда | Что делает |
|---|---|
| `pnpm dev` | генерирует контракт и запускает spec + сервер + клиент параллельно |
| `pnpm test` | генерирует контракт и прогоняет все тесты (сервер + клиент) |
| `pnpm build` | генерирует контракт, собирает клиент и проверяет типы сервера |
| `pnpm generate` | TypeSpec → `openapi.yaml` → `client/src/api/schema.d.ts` |
| `pnpm fixtures` | загружает стартовые фикстуры в запущенный сервер |

## Структура

```
spec/        TypeSpec-контракт (источник истины) и генерация openapi.yaml
server/      Fastify-приложение, доменная логика, HTTP-тесты
client/      React-приложение, страницы + RTL-тесты
fixtures/    стартовые фикстуры (CLI + общий модуль)
docs/        GRILLING-SESSION.md (решения), adr/ (ADR), idea/ (референс), agents/ (инструкции агентов)
GLOSSARY.md  доменные термины
```

## Тесты

Два шва (подробнее — в спеке, issue #1):

1. **HTTP API** (основной): вся доменная логика через внешнее поведение Fastify, включая контракт TypeSpec.
2. **Страницы**: пользовательские потоки гостя и админа через React Testing Library и фейковый HTTP-сервер.

```bash
pnpm test        # 42 теста: 25 сервер + 17 клиент
```

## Границы проекта (out of scope)

- Авторизация и защита админки (демо — админка открыта по `#admin`)
- База данных: состояние теряется при рестарте
- Отправка email (адрес только хранится), внешние интеграции, деплой
- Типы встреч и комментарий к записи
- Отмена/перенос/удаление записей

Решения и их обоснования — в `docs/GRILLING-SESSION.md`, `docs/adr/`, термины — в `GLOSSARY.md`.
