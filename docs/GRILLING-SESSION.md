## Суть

«Запись на звонок» — упрощённый Cal.com без авторизации. Один владелец публикует доступное время, гость без регистрации выбирает день в календаре месяца, свободный 30-минутный слот и записывается. Небольшое, но законченное приложение; разработка **локально**, деплой в облако вне объёма.

## Границы (чего НЕТ)

- авторизация, аккаунты, личные кабинеты
- интеграции с внешними календарями, отправка email
- деплой в облако (только локальная машина)
- типы встреч и их CRUD
- комментарий к записи
- отмена/перенос записей (гостем или админом)

## Владелец и админка

- Хост без аккаунта; бейдж «admin/Хост» в интерфейсе гостя убран.
- Админка **без защиты** (демо) и **без ссылки в навигации** — открывается по hash-маршруту `#admin`.
- Админка управляет **только событиями админа**: создание интервала и удаление. Список записей в админке не показывается.

## Слоты и время

- Окно бронирования: **09:00–18:00 UTC+3**.
- Хранение в **UTC**, отображение **UTC+3** (захардкоженный дефолт).
- Сетка всегда фиксированная: **30 минут**, **18 слотов в день**. Слоты показываются диапазоном («09:00 - 09:30»).
- Календарь: **месяц** — сетка **6×7 пн–вс** (42 дня, с понедельника недели 1-го числа), листается по месяцам (← →); слоты считаются **на лету** для просматриваемого месяца. Прошедшее время не показывается.
- День **не выбирается автоматически**: до клика по дате панель показывает «Выберите дату в календаре.».
- **События админа**: интервалы поверх сетки; пересекающиеся слоты помечаются «Занято». Сетка при этом не сужается. Событие валидируется в окне 09:00–18:00 UTC+3.
- **Антидубль**: одно время нельзя занять дважды — проверка пересечений с записями и событиями на сервере, конфликт → **409**.
- Состояние **in-memory**, без БД — теряется при рестарте.
- **Фикстуры** — стартовый набор данных (2 события админа + 2 демо-записи), загружается **командой вручную** (не автоматически).

## Сценарий гостя

1. Лендинг «Calendar» → «Записаться →»
2. Экран записи: «Информация» | «Календарь» | «Статус слотов». День не выбран → «Выберите дату в календаре.»
3. Клик по дате → слоты диапазонами и статусами; клик по свободному слоту (панель «Выбранное время») → «Продолжить»
4. Панель «Подтверждение записи»: **имя\*, email\*** → «Подтвердить запись»; «Изменить» возвращает к выбору слота
5. Успех: «Бронь подтверждена. До встречи!» + «Забронировать еще» (чистый экран записи)
6. «Назад» на экране выбора слота возвращает на лендинг

## Публичная страница «Предстоящие события»

- Открывается из навигации, доступна без авторизации.
- Показывает будущие записи: имя, email, «Слот: ДД.ММ.ГГГГ, ЧЧ:ММ», «Создано: ДД.ММ.ГГГГ, ЧЧ:ММ».
- Без записей — «Пока нет событий».

## Технологии

- TypeScript везде: **Fastify** (сервер), **React + Vite** (клиент), состояние в памяти
- **TypeSpec — источник истины** → `openapi.yaml` → клиентский SDK + схемы валидации сервера
- Структура: `spec/` + `server/` + `client/` в одном pnpm-репо
- Язык UI — русский; документы и обсуждения — русский

## Отклонения от исходного ТЗ (осознанные)

- ТЗ: «календарь на ближайшие 14 дней» → здесь: **динамические месяцы (сетка 6×7), расчёт на лету**
- ТЗ/макет: имя хоста «Tota» → бейдж хоста убран совсем
- Макет: слоты диапазоном («09:00 - 09:15») → здесь: **диапазоны фиксированных 30-минутных слотов** («09:00 - 09:30»)
- Добавлено: **события админа** поверх фиксированной сетки (блокируют пересекающиеся слоты, но не сужают сетку)
- Референс `docs/idea/` признан главным источником: типы встреч и комментарий удалены, добавлены лендинг, публичная страница событий и hash-админка
