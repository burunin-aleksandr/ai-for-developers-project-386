# Протокол сессии: общее понимание проекта

Дата: 2026-11-02
Формат: интервью (grilling), фронт закрыт — открытых вопросов нет.
Термины — в [`GLOSSARY.md`](../../GLOSSARY.md).

## Суть

«Запись на звонок» — упрощённый Cal.com без авторизации. Один владелец публикует доступное время, гость без регистрации выбирает тип встречи, свободный слот и записывается. Небольшое, но законченное приложение; разработка **локально**, деплой в облако вне объёма.

## Границы (чего НЕТ)

- авторизация, аккаунты, личные кабинеты
- интеграции с внешними календарями, отправка email
- деплой в облако (только локальная машина)
- публичная страница «Предстоящие события»
- удаление типов встреч
- отмена/перенос записей (гостем или админом)

## Владелец и админка

- Хост: имя **«admin»**, дефолтный аватар (второй вариант из обсуждения — «Tota» на макете; взято «admin»).
- Админка **без защиты** (демо).
- Админка: **создание и редактирование** типов встреч (удаления нет) + список предстоящих записей **только для просмотра** (тип, дата, время).
- Тип встречи: название, описание, длительность — **пресеты 15/30/45/60 минут**.

## Слоты и время

- Окно бронирования: **10:00–18:00**.
- Хранение в **UTC**, отображение **UTC+3** (захардкоженный дефолт).
- Календарь: неделя **пн–вс**, листается динамически (← →); слоты считаются **на лету** для просматриваемой недели, без предгенерации на год. Прошедшее время текущей недели не показывается.
- **Сетка-плейсхолдер**: шаг 15 минут внутри окна; видна и бронируется, когда нет событий админа.
- **События админа**: интервалы поверх сетки; пока есть хотя бы одно — гость видит только их; удалил все → возвращается дефолтная сетка. Внутри события слоты нарезаются **длительностью типа**, бронируется **только целым слотом**.
- **Антидубль**: одно время нельзя занять дважды, даже разными типами — проверка пересечений на сервере, конфликт → **409**.
- Состояние **in-memory**, без БД — теряется при рестарте.
- Пустой список типов → заглушка **«Типы встреч не созданы»**.
- **Фикстуры** — стартовый набор данных, загружается **командой вручную** (не автоматически).

## Сценарий гостя

1. Лендинг «Calendar» → «Записаться»
2. Выбор типа встречи (карточки)
3. Календарь недели + слоты → клик по слоту (панель «Выбранное время») → «Продолжить»
4. Форма: **имя\*, email\*, комментарий** → «Записаться»
5. Индикация успеха со сводкой (без кнопки отмены)

## Технологии

- TypeScript везде: **Fastify** (сервер), **React + Vite** (клиент), состояние в памяти
- **TypeSpec — источник истины** → `openapi.yaml` → клиентский SDK + схемы валидации сервера
- Структура: `spec/` + `server/` + `client/` в одном pnpm-репо (может быть разнесена позже)
- Язык UI — русский; документы и обсуждения — русский

## Отклонения от исходного ТЗ (осознанные)

- ТЗ: «календарь на ближайшие 14 дней» → здесь: **динамические недели пн–вс, расчёт на лету**
- ТЗ/макет: имя хоста «Tota» → здесь: **«admin»**
- Макет: слоты диапазоном («09:00 - 09:15») → здесь: **время начала слота** (контракт тестов — точный текст «10:00»)
- Макет: в календаре только месяц → здесь: **месяц + строка диапазона недели** «DD.MM.YYYY — DD.MM.YYYY» (контракт тестов)
- Добавлено: **события админа** поверх дефолтной сетки и правило их видимости
