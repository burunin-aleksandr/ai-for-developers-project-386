# Глоссарий

Словарь доменных пониманий проекта «Запись на звонок» (calendar-app).
Формулировки здесь — источник истины для терминов в коде, ТЗ, issue и спецификациях.

## Общее

- **Запись на звонок** — упрощённый сервис бронирования времени по мотивам Cal.com. Один владелец публикует доступное время, гость без регистрации выбирает свободный слот и записывается.
- **Владелец (хост)** — единственный владелец календаря в приложении, задан заранее. Имя — «admin», дефолтный аватар. Не имеет аккаунта и авторизации.
- **Гость** — пользователь, который бронирует слот. Приходит без регистрации, данные указывает при бронировании, отменить запись не может.

## Типы встреч

- **Тип встречи** — карточка, которую создаёт владелец: название, описание, длительность. Длительность — только одно из пресетов: **15 / 30 / 45 / 60 минут**.
- **CRUD типов** — в админке только **создание и редактирование**. **Удаления типов нет.**

## Время и слоты

- **Окно бронирования** — фиксированный рабочий интервал дня: **10:00–18:00**.
- **Слот** — минимальный интервал, который можно занять. Длительность слота = длительность выбранного типа встречи. Бронируется **только целиком**, частично занять слот нельзя.
- **Сетка-плейсхолдер** — дефолтная сетка слотов с шагом **15 минут** внутри окна бронирования. Видна и бронируется, когда владелец не создал ни одного события админа.
- **Событие админа** — интервал времени, созданный владельцем поверх сетки (например «вторник 10:00–11:30»). Пока существует хотя бы одно событие, гость видит **только их**; после удаления всех событий возвращается сетка-плейсхолдер. Внутри события слоты нарезаются длительностью типа встречи.
- **Занятость (антидубль)** — одно время нельзя занять дважды, даже разными типами встреч. Проверка пересечений интервалов на сервере; конфликт → **409 Conflict**.
- **Неделя** — единица отображения календаря: **пн–вс**. Слоты считаются **на лету** для просматриваемой недели (без предгенерации на год вперёд). Недели листаются динамически (← →). Прошедшее время текущей недели не показывается.

## Хранение

- **In-memory состояние** — все данные живут в памяти сервера, без БД. Записи и типы теряются при рестарте.
- **Фикстуры** — стартовый набор данных (типы встреч, расписание), загружается **командой вручную** (`pnpm fixtures` при запущенном сервере), не автоматически. При чистом старте (без фикстур и типов) гость видит заглушку «Типы встреч не созданы».
- **Часовой пояс** — хранение в **UTC**, отображение в **UTC+3** (захардкоженный дефолт).

## Запись гостя (бронирование)

- **Форма брони** — имя\*, email\*, комментарий (необязательный). Email только хранится, письма не отправляются (внешние интеграции запрещены).
- **Индикация успеха** — экран/сообщение после «Записаться» со сводкой (тип, дата, время). Отдельного «подтверждения» с повторным действием нет.
- **Предстоящая запись** — будущая запись гостя. В админке видна только для просмотра: тип, дата, время. Имя и email гостя хранятся в записи, но изменить/отменить её нельзя.

## Чего нет (границы проекта)

Авторизация и аккаунты; интеграции с внешними календарями; отправка email; деплой в облако (только локальная разработка); публичная страница «Предстоящие события»; удаление типов встреч; отмена записей (гостем или админом).
